# 房间动作事件与状态快照交接规则

本规则供后续逐个迁移技能时使用。本步不新增动作事件，也不改变当前技能的收发方式。A 仍负责执行、命中、数值和生命周期；B 的显示对象不参与结算。

1. **请求与执行**：B 的一次按键用该请求流的 `requestSeq` 表示意图。A 按连接确认玩家身份，接受后才分配实例 ID 和起始 `authorityTick`；拒绝不得启动成功冷却。执行确认必须能指出请求序号、接受或拒绝、实例 ID 和起始 tick。不同传输通道之间不假定到达顺序。
2. **实例建立与校正**：B 只由 A 的可靠执行确认建立实例。周期快照按本实体/本状态流递增的 `stateSeq` 和不回退的 `authorityTick` 校正已建立实例的位置、阶段和持续状态；同一实例的重复快照不得重启动画。快照先于确认到达时，不凭快照生成实例；确认到达后用其起始 tick 建立，后续新快照再校正。
3. **结束与退役**：A 对实例的取消或结束必须以可靠消息或可恢复的权威状态明确表达。B 记录已结束的实例 ID；迟到的开始消息、旧快照和重复结束消息都不能复活它。新房间、离房、断线或共同重试清理实例与预表现记录；同一房间内的旧实例 ID 不重用。
4. **结果结算**：伤害、死亡、掉落、拾取和资源只由 A 的结果驱动。`AuthorityResultReceipts` 按房间和精确 `resultId` 去重，允许编号空洞及跨流乱序；目标健康/资源还用各自版本与权威 tick 拒绝旧覆盖。结果可先于显示实例到达，B 仍按结果只结算和表现一次，不等待动画或补做本地命中。
5. **现有流程边界**：当前玩家/怪物攻击动画和技能对象仍有从快照发现实例的旧路径；逐项迁移时再改为上述事件建立规则。`AuthorityPositionBuffer` 已按实体位置流拒绝旧 `stateSeq`/tick，且玩家与怪物攻击退出后拒绝旧实例复活。当前技能状态流的可靠性及其独立序号规则保持原状，本步不假装已有独立执行确认消息。
