# 2D RPG 基础设施演进方案

状态：设计基线，尚未完成运行时代码迁移。2026-11-02。

## 目标与约束

以现有横版 RPG 为验证场景，建设可复用的模块、配置、资源、导航和双人协作基础设施。每项基础设施需要有接入样例、失败处理和可观测结果；不以接口数量或第三方库数量作为完成标准。

当前 Unity 为 2021.3.45f2c1。先保留现有物理、动画及战斗行为。引擎升级单独验证。现有 MainScene、Enemy Skeleton prefab、PlayerWallJumpState 的用户修改必须保留。

## 依赖边界

- Core：纯 C# 模块生命周期、显式依赖、类型化事件、时钟、取消与释放契约。不引用 UnityEngine 或具体玩法。
- Infrastructure：配置加载、资源、池、存档、网络传输、日志和指标。
- Gameplay：技能、效果、背包、任务、AI；依赖 Core 与基础设施接口。
- UnityAdapters：Physics2D、Animator、场景、资源后端、导航数据烘焙。
- Presentation：UI、输入、镜头、音效与特效；通过应用服务调用及事件显示结果。
- Bootstrap：组合模块，验证依赖，按顺序初始化，失败时逆序回收。
- Tools：配置生成、资源构建、导航可视化、压力场景及构建检查。

具体命名空间与程序集数量随第一阶段依赖梳理确定。新的 asmdef 不直接引用 Assembly-CSharp；用适配器逐步接入旧脚本，避免一次移动全部脚本。

## 模块、事件与调度

模块具备初始化、就绪、更新和释放语义，禁止用字典遍历顺序代替依赖排序。注册阶段与初始化阶段分离；检测缺失依赖和环。

事件使用类型化载荷；订阅返回可释放句柄。同步领域操作直接调用服务；事件通知已发生的事实，不把逐帧位置、每次物理查询都绕事件总线。网络线程只入队，Unity 主线程按预算派发。定义重入、订阅变化和异常处理规则。

本地可变速游戏时间、UI 实时时间和网络 tick 分开管理。输入锁按来源持有与释放，避免多面板叠加时提前解锁。

## Luban 配置管线

固定生成器版本，配置定义与输入数据进入版本管理；生成代码禁止手改。先选 JSON 便于排查，之后以实测决定是否切二进制。

第一批表：Skill、Effect、Enemy、Quest、QuestObjective、Item、DropTable。校验重复 ID、引用存在性、取值范围、任务前置环与资源键有效性。失败时生成命令返回非零退出码；同一命令可在本地与 CI 重现。

Luban 管共享配置；冷却、血量、任务进度属于角色运行状态。客户端和服务端分别生成所需数据视图，并在握手中校验兼容版本。只在启动或安全切换点替换完整配置快照，避免一次战斗混用两个版本。

现有物品使用 GUID 字符串 ID，先保留或提供稳定映射及存档迁移；禁止直接改成新整数 ID 导致旧档失效。ScriptableObject 可继续作为美术编辑或资源绑定入口，同一字段必须明确唯一数据来源。

## 技能与任务

技能按定义、运行实例、执行与表现分离。第一批效果执行器只覆盖伤害、治疗、位移、状态与生成对象；配置组合已有行为，新行为仍需要代码。

任务引擎消费击杀、拾取和交互等事实事件，按玩家和目标实体归属计数；处理重复事件、读档恢复和奖励幂等。双人时奖励由权威端确认。

## 对象池与资源

对象池先接伤害数字、命中特效和残影。池提供预热、容量、取出、归还、清空与指标。对象租借需要防重复归还，并清除 Invoke、协程、事件、碰撞、透明度和上次目标。旧延迟 Destroy 必须一起移除。资源句柄与池生命周期绑定，池清空后才能释放所持资源。

资源接口定义异步加载、取消、失败和显式释放；首先用旧资源适配器保证可迁移，再接 Addressables。更新链路包括 Catalog 检查、下载量、进度、失败重试、兼容检查、旧资源清理和发布验证。保存每个可更新客户端构建对应的 content state 文件。资源更新不能添加客户端尚不支持的代码行为。

## 横版导航、物理和 AI

当前 SkeletonBattleState 直接按玩家 X 方向设置速度；Entity 已提供地面、墙壁射线和攻击范围。

导航图的节点表示可站立区域，边表示 Walk、Jump、Drop；边成本与可通过性考虑角色尺寸、跳跃能力和净空。先实现静态地图 A*、路径调试显示、不可达结果和请求预算；动态障碍通过局部查询、失效检测与限频重规划逐步支持。

AI 负责选择目标与动作；路径规划负责生成路径；运动执行器负责速度、跳跃和落地；Physics2D 负责当前场景碰撞。不得用路径点瞬移替代物理运动，也不让规划器直接操作 Rigidbody2D。运行时仍检测墙、悬崖、头顶空间和卡住超时。

命中抽象为来源、目标、技能实例、攻击序号与结果，处理重复碰撞回调；寻路、身体碰撞和攻击判定是不同职责。

## 双人协作

首个目标为主机权威、单房间双人协作。将传输、会话、实体身份、输入命令、快照复制与表现分开。纯逻辑尽量可复用，未来可迁独立服务器；当前不宣称已经支持独立服务器。

怪物 AI、伤害、掉落和任务奖励由主机裁决。远端提交输入或动作请求，不能直接提交最终奖励。复制实体使用稳定网络 ID；使用输入序号、tick、快照时间、远端插值缓冲和断线生命周期。阶段性实现本地预测与校正，不能把两个 Physics2D 客户端视为天然确定性模拟。

TCP 可先覆盖房间和可靠业务，移动同步通过相同复制接口验证；遇到队头阻塞等实测问题再替换实时传输。断线重连需要会话恢复和状态重建，不能只重连 socket。

## DOTS / Jobs / Burst

主线先采取数据与表现分离，不接入旧版预览 Entities。Entities 1.0 官方要求 Unity 2022.3 起；完整 ECS 接入需单独升级分支和依赖验证。

独立性能场景比较串行与 Jobs/Burst 的目标距离筛选、感知和批量数值更新。输入为主线程收集的纯数据快照，输出在主线程应用；不在普通 job 中调用 GameObject、Animator 或现有 Physics2D 查询。记录数据拷贝、调度和同步成本。只有端到端收益成立再接主线；数据驱动不等于必须使用 ECS。

## 交付与验收顺序

1. 基线：确认编辑器编译、构建和现有操作，记录战斗性能及用户修改。
2. Core：模块依赖、失败回收、事件订阅释放测试；接入一个旧系统并验证行为。
3. 配置：可重现的 Luban 生成与校验命令，一种技能和一种怪物读表；保留旧存档兼容。
4. 池与资源：接入伤害数字和命中特效，验证状态重置、容量与资源释放，记录前后性能。
5. 导航：演示绕行、跳台、不可达及卡住处理，带图与路径可视化。
6. 任务：击杀与拾取驱动任务，奖励不重复，存取档后进度正确。
7. 更新：实际播放器从本地资源服获取新内容，网络失败可恢复，旧构建兼容策略明确。
8. 双人：两台客户端进入同图、战斗、拾取和奖励一致，断线行为明确。
9. 性能实验：独立批量计算基准，按测量结果决定 Jobs/Burst 和后续 Entities 升级。
