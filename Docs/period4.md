拆分需要考虑这些实际情况：
- mmo-demo 的 NetPacket 已有循环读取完整数据的逻辑，但字节序依赖 BitConverter，需要明确约定。
- NetSystem 可以参考收发、队列和主线程派发；现有退出逻辑还需要补线程结束、队列清理和会话隔离。
- rpg 的 PlayerManager、`SkillManager`、伤害、掉落和拾取目前主要按单玩家设计。第二名玩家的输入、技能、背包和奖励归属必须逐项适配。
- LocalPlayerStateSender 的客户端位置上报只能作为结构参考，需要改成“B 发输入，A 计算，A 发权威状态”。

下面每个编号代表一次独立修改。其中“本次只做什么”限定当次范围，“验收小目标”通过后再继续。新增或修改 UI 的准备项必须在首次业务使用前写明，先完成界面引用、数据归属和模拟状态准备，再接业务。


## 统一实施约定

1. 首版限定 A、B 两人，通过 IP＋端口直连；先验收同机，再验收局域网。
2. 首版房间固定使用 MainScene，不扩展跨地图联机。
3. A 同时运行本地玩家和两名玩家的权威模拟；B 采集自己的输入、显示 A 同步的结果。
4. A → B 的角色状态默认每 100ms 发送一次；B → A 的移动输入单独设计，采用“当前状态变化触发＋默认 40ms 最小发送间隔（可配置 30～50ms）＋100ms 周期补发”，间隔内合并最新状态（含松键零值）。跳跃、攻击等按下动作使用请求序号，避免重复执行。
5. 单机模式保留。尚未完成网络适配的操作，在联机测试中明确限制，避免两端各自运行后产生假同步。
6. 每次说明旧流程、新流程、改动范围及操作验收方法。存在依赖时，只接通当前小功能所需的入口。
7. 前期通过临时验证入口测试底层功能，不为每一步创建 UI。
8. 协议、状态排序、结果去重、当前输入状态及非缩放权威模拟均遵守下述前置一致性规则；后续 65 步统一引用，不重复定义。

| 4-57 | 同步掉落运动。 A 模拟落物物理并同步位置、落地状态，B 只显示，避免随机速度和碰撞使两端落点分离。 A 的掉落物理使用统一非缩放模拟时间；B 复用实体权限组件，仅按 authorityTick/stateSeq 显示或插值，不启用自主物理。 | 掉落落地后两端位置一致；B 的本地物理不会推走权威掉落。 |
| 4-58 | 建立各玩家的房间背包。 复用 InventoryModel、`InventorySystem` 规则，为 A、B 分别保存房间内物品、容量及版本；将前面战斗使用的物品状态接到明确玩家名下。 | A 校验 B 的容量时读取 B 的背包；两名玩家添加测试物品互不影响；B 只能显示自己收到的背包数据。 |
| 4-59 | 接通拾取请求。 将 ItemObjectTrigger 的本地直接入包改为申请拾取；A 根据连接确定玩家，校验存活、距离、掉落存在及背包容量。 | 超距离、死亡、背包已满和不存在的掉落均被拒绝；拒绝后物品仍保留。 |
| 4-60 | 完成拾取唯一归属。 A 在一次主线程处理内完成“校验→入包→标记已领取→广播移除”；按请求 ID、掉落 ID 和背包版本防重复应用。 拾取确认和移除结果同时携带统一 resultId、authorityTick、请求序号、dropId 和该玩家背包版本；请求重放、结果重放、重复移除分别幂等。背包版本断档时获取当前清单，不盲目累加。 | A、B 同时拾取同一物品时只有一人获得；重放请求和结果均不重复入包；两端物品一起消失。 重放结果不重复入包或移除，背包版本断档能恢复清单。 |
| 4-61 | 同步怪物货币奖励。 移除 EnemyStats 对全局玩家货币的直接增加；首版约定由最后一次有效伤害的来源玩家获得，分身、飞剑等追溯主人。 | B 击杀不会错误加给 A；两端奖励数额及归属一致；一次死亡只发一次。 |
| 4-62 | 同步玩家死亡损失。 适配现有死亡掉币、掉物规则，由 A 决定损失及生成结果；死亡货币标记原主人，物品归属采用明确规则。 | 死亡不会扣另一人的货币或背包；两端损失及掉落实体一致；重复死亡事件不重复扣除。 |
| 4-63 | 隔离联机数据与单机存档。 明确房间临时数据的退出处理，拦截网络副本触发的自动保存、检查点恢复及重复存档注册；首版房间收益先不写入单机存档。 | 正常离房、A 关闭和 B 异常断线均不污染单机存档；重新进入单机可正常读档。 |
| 4-64 | 补齐入房时的当前世界快照。 新加入玩家在场景就绪后，获得当前玩家、怪物、死亡状态和未领取掉落，再切换到增量同步；用快照版本避免应用期间漏消息。 快照携带 authorityTick 和对应状态/结果基线，切换增量时沿用相同排序与去重规则，避免旧状态或重复结果污染当前世界。 | A 已移动、打伤怪物、击杀或拾取后 B 再加入，看到当前世界；不复活死怪、不恢复已领取掉落。 |
| 4-65 | 清理断线玩家的派生资源。 在既有离房清理入口补上飞剑、分身、水晶、黑洞、持续效果、待执行请求和怪物目标引用；已落地公共掉落保留。 同时清空当前会话的插值缓存、输入/状态序号及结果去重记录，旧会话回调不得刷新新实体或 UI。 | B 断线后没有幽灵攻击、永久控制或残留目标；A 退出后 B 清空整个房间资源；下一次入房没有旧消息和旧对象。 |


其中 4-58 是背包归属的完整落地；`4-30～4-31` 先提供战斗需要的最小玩家数据，`4-41～4-44` 接入相关操作。实施时使用同一份玩家上下文逐步补充，避免建立两套背包或战斗数据。

## 最终验收分四次进行


每次只验证一个范围；发现问题后单独安排修复，不夹带新功能。
1. 房间与移动验收： 同机双客户端完成创建、加入、双方移动及动画；核对实际消息方向、内容和发送频率。
2. 战斗验收： 两人分别攻击、被怪物攻击，验证普通攻击、已接入技能、元素效果及生命值一致。
3. 死亡与收益验收： 验证怪物/玩家死亡、掉落、背包满、同时拾取、重复请求和奖励归属。
4. 会话与局域网验收： 验证 A 退出、B 退出、强制关闭、连接超时、再次加入及完整清理；核对旧会话状态/结果隔离及所有已接入模块在联机菜单下继续推进；同机通过后再进行局域网双机测试，记录 Windows 防火墙放行或拦截现象。
后续开始实施时，第一项是 4-01：迁移并验证封包协议，同时建立唯一协议目录、最小 DTO、统一编解码入口和 SchemaVersion。完成该项不会同时复制整个 NetSystem 或修改游戏玩法。
